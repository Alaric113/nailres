1. 手動發送優惠券搜尋會員崩潰 (亂碼錯誤)
src/components/admin/CouponDistribution.tsx
Bug 修復
問題原因： 當手動發送優惠券並搜尋會員時，程式會執行 user.email.toLowerCase()。但使用 LINE 快速登入或資料庫中 Email 欄位缺失時，會直接觸發 undefined is not an object (evaluating 'm.email.toLowerCase') 錯誤畫面。
修復方案： 加入安全可選鏈接與空字串預設防護 (user.email || '').toLowerCase() 與 user.profile?.displayName，徹底防止因會員欄位缺失導致的畫面崩潰。
2. 管理員權限保護 (禁止修改自己的角色)
src/pages/CustomerListPage.tsx src/components/admin/UserCard.tsx netlify/functions/update-user-role.ts
安全性強化
問題原因： 管理員在客戶列表或手機卡片檢視中，下拉選單未限制自己，可能誤操作將自己從 admin 降級為一般會員導致系統管理權限喪失。
修復方案：
  • 前端 (UI)： 電腦版列表與手機卡片比對 auth.currentUser?.uid，對管理員本人的選單直接設為 disabled 禁選與灰色樣式。
  • 後端 (API)： 在 Netlify Function 中加入阻擋 targetUserId === requesterUid，伺服器端雙重防禦。
3. 客戶備註修改後需跳出重進才更新
src/pages/CustomerListPage.tsx
UX 體驗修復
問題原因： 在列表編輯備註點擊「儲存」後，程式成功將備註寫入 Firestore，但未重設編輯中狀態 setEditingUserId(null)，導致輸入框一直停留在編輯中狀態，使用者以為沒存成功，必須重新整理或切換頁面才會恢復正常文字顯示。
修復方案： 在 handleSaveNote 成功儲存的流程末端加入 setEditingUserId(null)，存檔後即時收合輸入框並在畫面上顯示最新純文字備註。
4. 客人端補睫售後服務「有時候不出現」之深層原因修復
src/hooks/useUserFollowUps.ts src/components/booking/FollowUpServiceCard.tsx src/components/booking/FollowUpSelectModal.tsx src/utils/bookingActions.ts
核心機制修復
問題原因：
  • 原因 A（生成遺漏）： 過去只有在「訂單管理頁面」點完成才會生成售後資格，從日曆看板、客戶詳情、編輯訂單完成都不會生成。
  • 原因 B（日期轉換崩潰）： 客人端讀取 fu.expiresAt.toDate() 時，若日期為快取或序列化物件（非 Timestamp 實例），會直接報錯並靜默將列表清空為 []。
  • 原因 C（代客預約遺漏）： 代客預約時未將目標客戶 ID 傳入售後 Hook，導致無法讀取客人的補睫資格。
修復方案：
  • 在 updateBookingStatus 核心全面自動生成售後服務資格。
  • 新增通用日期解析器 toJsDate()，相容 Timestamp、物件 {seconds} 與 Date 格式，徹底消滅靜默失敗。
  • 預約元件全面支援 targetUserId，代客預約與自訂皆可 100% 正常顯示售後優惠。
5. 消費金額餘額跨單累積機制 (Carryover Spending) ＆ 3個月滾動刷新
src/types/user.ts src/utils/bookingActions.ts src/components/dashboard/LoyaltyCard.tsx src/pages/CustomerDetailPage.tsx
全新機制
問題原因： 同一客人同天預約不同設計師被拆成兩張訂單（如睫毛 $1,800 + 指甲 $1,200 = $3,000），過去每張單獨立無條件捨去，分別只拿到 1 點與 1 點（合計僅 2 點，損失了 1 點）。
修復方案：
  • 跨單滾動累計： 第一筆 $1,800 兌換 1 點並保留餘額 $800；第二筆 $1,200 加上前次餘額 $800 合計 $2,000，自動換得 2 點，剩餘 $0，總計順利拿到 3 點！
  • 3 個月效期自動刷新： 每次只要有新消費完成，消費餘額有效期限即自動重設為 3 個月（90 天）。
  • 會員中心進度條： 在會員端集點卡片上直觀呈現「累積消費：$X / $1,000（尚差 $Y 可得 1 點）」及到期日。
  • 後台詳情與手動補發： 在後台客戶詳情頁同步顯示未兌換消費餘額，並可隨時手動微調/補發點數。
6. LINE 用戶更換頭貼致原 CDN 網址失效 (破圖防護與自動同步)
src/components/common/UserAvatar.tsx src/pages/CustomerListPage.tsx src/components/admin/UserCard.tsx src/components/dashboard/LoyaltyCard.tsx src/pages/CustomerDetailPage.tsx src/components/common/Sidebar.tsx
UX 容錯強化
問題原因： LINE 用戶一旦在 LINE App 更換個人頭像，LINE 伺服器會生成全新的隨機 CDN 網址，並在一段時間後將舊網址刪除（回傳 404/403）。若該客人尚未再次登入預約系統，後台及會員端讀取舊網址時會出現瀏覽器破圖圖示。
修復方案：
  • 建立共用 UserAvatar 元件： 內建 onError 破圖監聽。當 LINE 舊網址失效時，自動優雅降級為「顧客名字首字質感圓圈」或「預設大頭貼」，100% 杜絕破圖圖示。
  • 每次登入即時刷新： 客人只要開啟 LINE LIFF 或預約系統，後端登入函式會即時取得 LINE 當下最新 pictureUrl 並覆寫更新資料庫。
